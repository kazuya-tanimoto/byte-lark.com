こんにちは。私は個人サイトをClaude Codeで作っています。  
開発はdevcontainer（コンテナ）の中で、Claude Codeを全権限のまま自走させています。

これまで、コンテナでの隔離については[Claude Codeを全権限で自走させるなら、隔離が要る](/blog/claude-code-devcontainer)で、ターミナル環境のherdrについては[alacritty + tmuxからghostty + herdrへ乗り換えた](/blog/ghostty-herdr-migration)で書きました。  
herdrのサイドバーの見え方や状態の種類、通知の説明とスクリーンショットは乗り換えの記事にあるので、この記事では説明し直しません。

今回は、コンテナの中で動かしているClaude Codeをherdrのサイドバーに出す話です。  
サイドバーに出ないので、コンテナとMacを繋ぐ仕組みを自作して約7週間使ってきました。  
ところが最近になって公式ドキュメントを読み直したところ、起動コマンドに環境変数を1つ付けるだけで済むと分かりました。  
この記事では、出ない原因と公式の手段、それから見落とした経緯を書きます。

## コンテナのClaude Codeだけ、herdrのサイドバーに出ない

herdrは、ターミナルの作業空間を管理するツール（ターミナルマルチプレクサ）です。  
左のサイドバーに、動いているAIエージェントの一覧と状態（idle / working / blocked）が表示され、承認待ちや完了になるとmacOSの通知も届きます。  
手元のバージョンはherdr 0.9.0です。

普段の開発では、コンテナを起動してその中でClaude Codeを全権限で走らせる自作のfish関数`ccd`（中身は`devcontainer exec`の呼び出しです）を使っています。  
あるとき、herdrでペインを上下に分割し、上のペインでコンテナの中のClaude Codeを、下のペインで手元のMacのClaude Codeを動かしていました。

ところが、サイドバーのエージェント一覧にはMacのセッションしか表示されませんでした。  
欲しかった動作は次の3点です。

- コンテナのセッションの状態（動いている／応答待ち／承認待ち）をサイドバーで見たい
- 承認待ちや完了の通知を受け取りたい
- Macとコンテナで見え方を揃えたい

## herdrはMacの中のプロセスしか見えない

herdrはMacで動いていて、Macの中のプロセスしか見えません。  
各ペインについて、Mac上でいま動いているコマンドを見て、エージェントかどうかを判定します。  
MacでClaude Codeを直接起動したペインでは、動いているコマンドは`claude`なので、エージェントだと分かります。  
コンテナで起動したペインでは、Mac上で動いているコマンドは`devcontainer exec`です。  
Claude Code本体はコンテナの中で動いていて、Macのプロセス一覧には出てきません。  
そのため、herdrにはこのペインでClaude Codeが動いていると判定する材料がありません。

8月に調べた時点では「hookが申告しないから見えない」と考えていましたが、これは誤りでした。  
主な判定はMac上で動いているコマンドの検出で、hookはセッションを識別するために使われているだけでした。

## 起動コマンドに`HERDR_AGENT=claude`を付ける

公式ドキュメント（https://herdr.dev/docs/agents/ ）の「VMs and sandbox wrappers」節に、そのままの解決策がありました。  
ドキュメントには次のように書かれています。

> Set HERDR_AGENT=<agent> on the wrapper command… The hint applies only to that foreground process. Herdr cannot see it if you set it only inside a VM or container.

対応は、Macのherdrのペインで、コンテナに入るコマンドの頭に `HERDR_AGENT=claude` を付けるだけです。  
fishでの実例は次のようになります。

```fish
env HERDR_AGENT=claude devcontainer exec --workspace-folder ~/src/byte-lark.com claude
```

`--workspace-folder`には自分のプロジェクトのパスを指定します。bashやzshを使っている場合は先頭の`env`は不要です。

この環境変数はMac側のコマンドに付けます。  
コンテナの中で設定してもherdrからは見えないため、効果はありません。

この環境変数を付けると、Mac上で動いている`devcontainer exec`をclaudeとして扱うようherdrに指示が渡ります。  
あとはherdr自身がペインの画面を読んで状態を判定するため、コンテナの中にhookを入れる必要も、Macのソケットをコンテナに共有する必要もありません。  
コンテナからMacへ通じる経路を増やさないので、隔離環境の安全性も保たれます。

手元のMacのherdr 0.9.0で試したところ、自作の仕組みとまったく同じように動きました。

- サイドバーに行が出る
- 実行中と応答待ちが正しく切り替わる
- 承認待ちの状態が反映される
- 別のタブを開いていてもMacの通知が届く

hookも見張りのスクリプトも使わずに、この4つがすべて動作しました。  
この結果を見て、普段コンテナを起動している`ccd`も、この環境変数を付ける形に直しました。  
自作のhookと見張りは外しています。

実際の画面はこんな感じです。

【要写真：撮影リスト No.1（herdrのサイドバー。コンテナのセッションの行とMacのセッションの行が並んでいる状態）】  
*herdrのサイドバーに、コンテナのセッションとMacのセッションが並んでいる*

試した際に通知が出なくて少しハマりましたが、原因はなんてことはなく、macOSの集中モードを有効にしていました。  
通知が出ないときは、集中モードやおやすみモードになっていないか確かめてみてください。  
もう1つ、herdrは[いま見ているタブの通知は出さない仕様](https://herdr.dev/docs/configuration/)です。  
そのタブにいるエージェントの状態が変わっても通知は出ないので、別のタブを見ているときに確かめます。

## 公式の手段を見落とした経緯

いつから使えたのかを、herdrの変更履歴（CHANGELOG.md）で確認しました。  
`HERDR_AGENT`が追加されたのは、Linux向けが0.7.1（2026-06-24）、macOS向けが0.7.5（2026-07-21）でした。

私が自作の仕組みを作った2026年7月末の時点で、手元のMacで使っていたherdrは0.7.3でした。  
0.7.3のドキュメントには「On Linux, …」と記載されており、Linux限定の機能だったため手元の環境では使えませんでした。

しかし、macOSに対応した0.7.5は自作の仕組みを作る10日前にすでに公開されていました。  
バージョンを上げていれば使えたはずですが、0.7.5の変更履歴に並んでいた7項目のうちの1行だったため、見落としていました。  
なお、0.7.5のMacで実際に動くかは試しておらず、動作を確認したのは0.9.0だけです。

## 約7週間使っていた自作の仕組み

公式の手段に気づくまでの約7週間、どのように動かしていたかも簡単に触れておきます。

検討時にやめたのは、Macのソケットをコンテナに渡して公式のhookを動かす案でした。  
herdrのソケットにはペインの作成や文字の入力を行う権限があるため、コンテナに渡すとコンテナの中からMac上で自由なコマンドを実行できてしまいます。  
全権限で放置自走させるためにコンテナへ隔離している以上、これでは隔離の意味がなくなります。

そこで、一方通行の受け渡しを行う仕組みを作りました。  
コンテナ内のClaude Codeのhookが、Macと共有している作業ディレクトリに状態（working / idle / blocked）を1語だけ書き込みます。  
そのファイルをMac側の見張りスクリプトが読み取って、herdrに報告する構成です。これならコンテナからMacへの経路は増えません。

この自作の仕組みでも、約7週間のあいだサイドバーの表示と通知は常に役に立っていました。  
ただ、まれに1つのセッションだけサイドバーに出なくなる不便が残っていました。  
状態ファイルも見張りも正常に動いており、新しいペインを作って起動し直すと表示されるため、原因は不明のままです。

7週間も自作の仕組みを使っていましたが、結局公式でサポートされていたというオチでした。  
AIエージェントの時代なので、車輪の再発明をするのも悪くはないと思いますし、少しでも自分向けにカスタマイズできるなら、独自に作る価値は高いと思います。  
ただ、やはり公式が提供する機能には価値があるので、独自に作る前に最新の情報を調べたほうがいい、という教訓を得ました。

## まとめ

- コンテナ内のClaude Codeがherdrに表示されないのは、コンテナの中のプロセスがMacから見えず、herdrの判定が働かないため
- 起動コマンドの先頭に`HERDR_AGENT=claude`を付けるだけで、hookやソケット共有なしでサイドバー表示と通知が動く
- 設定はMac側のコマンドに付ける必要があり、コンテナ内で指定しても効果はない。コンテナからMacへの経路を増やさないため隔離も保たれる
- 足りない機能を感じたときは、独自に作る前に最新の情報を一度調べてみるといい

自作の仕組みは役に立ちましたが、先に調べていれば7週間分の手間は要りませんでした。
