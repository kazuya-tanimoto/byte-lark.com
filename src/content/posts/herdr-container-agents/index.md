こんにちは。今回はターミナルマルチプレクサのherdrと、コンテナ内で動かすClaude Codeの話です。  
普段は、Claude Codeを全権限で自走させるために[devcontainerで隔離した環境](/blog/claude-code-devcontainer)を用意し、ターミナル環境には[ghosttyとherdr](/blog/ghostty-herdr-migration)を使っています。

herdrを使うと、左サイドバーにエージェントの一覧が並び、実行中や応答待ちといった状態が一目で分かります。  
承認待ちや完了時にはmacOSの通知も届くため、複数のエージェントを動かすのに重宝しています。  
（herdrのサイドバーの見え方や状態の種類、通知については、先ほど挙げたghosttyとherdrの記事で詳しく触れています）

ところが、コンテナの中でClaude Codeを起動すると、herdrのサイドバーにセッションが表示されません。  
手元のMacで動かしているセッションは出るのに、コンテナのセッションだけ見えない状態でした。

そこで、コンテナとMacを繋ぐ自作の仕組みを作り、約7週間使ってきました。  
ですが最近になって、herdrの公式ドキュメントに、起動コマンドの先頭に環境変数を1つ付けるだけで解決する手段が書かれていることに気づきました。  
自作の仕組みを使わなくても、公式の手段だけで、コンテナ内のClaude Codeをherdrに認識させられます。

## コンテナ内のClaude Codeがherdrに認識されない原因

herdrは、各ペインの前面で動いているプロセスを見て、エージェントが動いているかを判定します（公式ドキュメントの「Status authority」節）。  
Claude Codeの場合、実行中や応答待ちといった状態は、herdrがそのペインの画面を読んで判定しています。

コンテナで動かすと、この最初の判定ができません。  
私は、コンテナに入ってClaude Codeを起動する自作のfish関数`ccd`を使っていて、中では`devcontainer exec`を呼んでいます。  
コンテナ内のプロセスはDockerの独立したプロセス空間で動くため、Mac側のプロセス一覧には現れません。  
herdrから見える前面プロセスは`devcontainer exec`だけで、Claude Codeが動いていると判定する材料がありませんでした。

Macでは`herdr integration install claude`でClaude Codeにhookが入りますが、コンテナの設定は専用のボリュームにあり、このhookは入っていません。  
MacのUnixソケットもコンテナからは見えないため、コンテナからherdrへ何かを伝える経路もありませんでした。

## 起動コマンドに`HERDR_AGENT=claude`を付ける

公式ドキュメントの[VMs and sandbox wrappers](https://herdr.dev/docs/agents/#vms-and-sandbox-wrappers)節に書かれていた解決策は、Macのherdrのペインで、コンテナに入るコマンドの先頭に`HERDR_AGENT=claude`を付けるだけでした。

fishでの実行例は次のようになります。

```fish
env HERDR_AGENT=claude devcontainer exec --workspace-folder ~/src/byte-lark.com claude
```

`--workspace-folder`には自分のプロジェクトのパスを指定します。  
bashやzshなら`env`は要らず、`HERDR_AGENT=claude devcontainer exec …`と書けます。

この環境変数は、Mac側のコマンドに付けます。  
コンテナの中で設定してもherdrからは見えないため、効果がありません（公式ドキュメントにもその旨が明記されています）。

仕組みとしては、herdrに対して「この前面プロセス（`devcontainer exec`）はClaudeとして扱ってほしい」というヒントを渡しています。  
ヒントを受け取ったherdrは、ペインの画面出力を直接読み取ってエージェントの状態を判定します。  
そのため、コンテナの中にhookを入れたり、Unixソケットを共有したりする必要がありません。  
コンテナからMacへ通じる経路を増やさないので、隔離はそのままです。

Mac（herdr 0.9.0）で試したところ、期待どおりに動きました。  
サイドバーにエージェントの行が追加され、実行中や応答待ちの切り替え、承認待ちの表示、そして別のタブを開いているときのmacOS通知まで、すべて自作の仕組みと同じように機能しました。  
試したのはここまでで、普段使っている`ccd`はまだ自作の仕組みのままです。

試した際に通知が届かないことがありましたが、調べてみるとmacOSの集中モードが原因でした。  
herdrは、現在表示しているアクティブなタブについては通知を出さない仕様になっています。  
通知が来ないと感じたときは、この2点を確認してみてください。

## 公式の手段を見落とした経緯と、約7週間使った自作の仕組み

コマンドに1つ付けるだけの公式の手段があるのに自作したのは、手元のherdrのバージョンが古く、新しい版の変更履歴にも気づいていなかったためです。

自作の仕組みを作った2026年7月末の時点で、Macに入っていたherdrは0.7.3でした。  
0.7.3のドキュメントをいま確認すると、`HERDR_AGENT`による指定は「On Linux, …」と書かれていて、Linux限定の機能でした。  
当時の手元のバージョンではMacに対応していませんでした。

herdrの変更履歴（CHANGELOG.md）を調べると、macOSへの対応が入ったのは2026年7月21日に公開された0.7.5でした。  
自作した日の10日前にリリースされていたため、herdrを最新版に更新していれば使えていたことになります。  
ただ、0.7.5の変更履歴では追加された7項目のうちの1行として記載されていて、気づいていませんでした。  
（なお、0.7.5のMacで実際に動くかは試しておらず、動作を確認したのは0.9.0です）

当時は公式の手段を知らないまま、自作の仕組みを作りました。  
コンテナにMacのUnixソケットを渡せばherdrと通信できます。  
ただ、それではコンテナ内からMac側で任意のコマンドを実行できる経路を渡すことになり、安全のために隔離した前提が崩れてしまいます。  
そこで、コンテナ側は共有ディレクトリに状態ファイル（workingやidleなど）を書き出すだけにとどめ、Mac側で待機させたスクリプトがそのファイルを監視してherdrへ報告する、一方通行の仕組みを組みました。

この自作の仕組みは約7週間使っていて、サイドバーの表示と通知は常に役に立っています。  
ただ、まれに特定のセッションだけサイドバーに表示されず、ペインを作り直して起動し直す必要があるといった原因不明の不便もあります。  
公式の手段を一度試したペインで自作の仕組みを動かしたときも、同じようにサイドバーに表示されなくなりました。  
確かめてはいませんが、公式の検出が一度働いたペインでは自作の報告が反映されないように見えます。同じペインで両方を混ぜないほうがよさそうです。

## まとめ

- コンテナ内のClaude Codeがherdrに認識されないのは、herdrから見える前面プロセスが`devcontainer exec`だけになり、中のClaude Codeが見えないため
- Macのherdrのペインで、コンテナに入るコマンドの先頭に`HERDR_AGENT=claude`を付けると、herdrが画面から状態を判定する（コンテナの中で設定しても効かない）
- 通知が届かないときは、macOSの集中モードやアクティブなタブでないかを確認する
