# AI 臭リライト事例集

運営者に「AI 臭い」と指摘された文と、確定したリライト後の文を対で貯める。
執筆・リライト・レビュー（article-review「AI 臭」軸）で before 側に似た表現を書いていないか照合し、after 側を文体の手本にする。
ルールの一覧は profile.md「避ける表現」にあり、ここはその実例編。運営者の指摘原文と確定文だけを載せ、要約で薄めない。

## 記事 T8「alacritty + tmux から ghostty + herdr へ乗り換えた」（2026-09-09、PHASE1E-008）

### プレゼン的な前振り・種明かしのキメ文

- before：「決め手は2つでした。／エージェントの状態を設定なしで検知して見せてくれることと、キーバインドがtmux互換で学習コストが低そうなことです。」
- after：「決め手は、エージェントの状態を設定なしで検知して見せてくれるところと、キーバインドがtmux互換で学習コストが低そうなところでした。」
- 指摘原文：「特に『決め手は2つでした。』とかAI臭すぎる」「数を書くのがダメじゃないのよね。『不満点は強いて挙げると2つあります』とかだと全然普通でしょ。キメにいくというか格好つけるというか、、AIってこういう書き方よくするやん？それがプンプン臭う使い方がダメなのよ」

### 「一般論 → 私はこう使っています → 箇条書き」の教科書的な運び

- before：「herdrの公式ドキュメントは、workspaceを〜勧めています。／私はこう使っています。／（箇条書き 3 点）」
- after：「herdrの公式ドキュメントには〜とあります。／私もこれに倣って、リポジトリごとにspaceを分け、その中でタスクごとにタブを作成し、1タスクに1エージェントを走らせています。」
- 指摘原文：「とかの文章構成もザ・AIだよね。。」

### 機能を擬人化する「付いてきました」と、地の文に均された実感

- before：「実際に入れてみると、tmuxでやっていたことはそのままできて、そのうえで状態の可視化と通知が付いてきました。いいやん、となってそのまま定着しました。」
- after（運営者リライト）：「実際に入れてみると、tmuxでやっていたことはそのままでき、加えてエージェントの状態の可視化や通知ができます。／『これはいいぞ！』となってそのまま定着しました。」
- 指摘原文：「『そのうえで状態の可視化と通知が付いてきました』の付いてきましたもAI臭くてNG」
- 学び：実感はかぎ括弧 + ！で本人の声として書く。地の文に溶かすと温度が消える

### 地の文の断定 → 自分の声のかぎ括弧

- before：「tmuxの上位互換になりそうだと思って試してみました。」
- after（運営者リライト）：「『これはtmuxのAIエージェント向け上位互換かも？』と思って試してみました。」

### 断定でキメる一文 → 留保を足して話し言葉に

- before：「一言でいうと、tmuxをAIエージェント向けに再構築したものです。」
- after（運営者リライト）：「一言でいうと、tmuxをAIエージェント向けに再構築したもの、というイメージかと思います。」

### 詩的・抽象な単語だけの見出し

- before：「## きっかけ」
- after（運営者リライト）：「## 導入のきっかけ」
- 指摘原文：「タイトルが詩的なのがAI臭くてNG」

### こなれた圧縮動詞（割る・足す）

- before：「その中をタスクごとのタブに割って、1タスクに1エージェントを走らせています。一時的なコマンド実行はペイン分割で足します。」
- after（運営者リライト）：「その中でタスクごとにタブを作成し、1タスクに1エージェントを走らせています。／一時的なコマンド実行やメモなどが必要な場合はタブ内を複数ペインに分割して行っています。」
- 運営者が「タブに割って」「ペイン分割で足します」を名指しで NG とした

### 大げさな言い回し

- before：「いまはghostty + herdrが標準になっています。」
- after（運営者リライト）：「いまはghostty + herdrを使っています。」

### 開発者の内輪語

- before：「repoごとにspaceを分け」
- after：「リポジトリごとにspaceを分け」
- 指摘原文：「記事なので誰にでも通じるワードにしてください。repoって全員が使いはしないよ」
