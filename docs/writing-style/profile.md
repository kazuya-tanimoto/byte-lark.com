## 避ける表現

（例: 過剰な敬語、「させていただく」系、など）

- 他者の選択を腐す言い回し（「mailto は無いですよね。普通に。」等）。自分がなぜ採用しなかったかだけを淡々と書く（2026-08-01 PHASE1B-009 ドラフトへの運営者指摘）
- 地の文での体言止めの多用（「不採用。」「〜だけ。」等）。文を短くするときも文末は です・ます で言い切る。体言止めは効かせたい所にたまにだけ。箇条書きの中は言い切りで可（2026-08-02 同上）
- 読者に前提知識を仮定した説明（「管理するサーバーを増やしていない」等）。仕組みの前提（配信は何がやっているか、処理はどこで動くか）を先に普通の言葉で説明してから本題に入る。最低限の IT 知識で通じるかを毎回自問する（同上）
- 上記「前提知識を仮定しない」の適用先は仕組みの前提だけ。静的サイト・エスケープ・レスポンス等の Web 開発基礎用語をふわっとした日本語（「窓口」「置き場」「返事」等）に言い換えることには適用しない。tech 記事の対象読者はエンジニア（当該分野の未経験は可）（2026-08-02 PHASE1B-009 リライトへの運営者指摘）
- 固有の仕組みを曖昧な代名詞（「自作プログラム」等）で呼び続けない。正式名称を初出で 1 回定義し、以後その名前で使い回す（同上）
