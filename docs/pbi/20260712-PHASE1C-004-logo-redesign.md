### 2026-08-01（コンテナ・着手 → 前提調査 → 合格条件確定 → 旧案待ち）

#### 着手前に判明した前提のズレ

- Header はテキストだけだった。`src/components/Header.astro` の `byte-lark` という文字（`font-heading text-lg font-bold`）がロゴの位置に置かれており、画像は使っていない
- `src/assets/logo.png` は `src/` のどこからも参照されていない未使用ファイル（`grep -rn logo src/` でヒットなし）。受け入れ条件の「Header の現行 logo.png 参照を置換」は成り立たないので、「テキストワードマークの置換 + 未参照 png の処置」に書き換えた
- 旧 ChatGPT 案 2 種はリポジトリに存在しない（`find -iname "*logo*"` で `logo.png` と本 PBI のみ）。運営者が画像を渡す判断のため、ラウンド 1 は受領後に開始する
- ClaudeDesign は PHASE1C-001 時点で利用不可（design-direction §1）。本 PBI も HTML モック + スクショのフォールバックで進める

#### 意匠の入力は既にサイト上にある

PHASE1C-008 で Hero に実装した署名要素（`src/components/Hero.astro`）が、そのままロゴの語彙になる：点線（`stroke-dasharray="1 10"`）で左下から右上へ昇る軌跡 + ヒバリのシルエット（2 パスの簡略形）+ 朝日（radial-gradient の円、sun → sun-light）。design-direction §6 の 004 への申し送り「sky 基調 + sun 差し色 / 軽やか・上昇 / Hero の飛行線モチーフと整合」と一致するので、ゼロからの意匠探索は不要。

#### 運営者判断（3 件）

- 合格条件チェックリストは提案 6 項目で確定（本文の「合格条件チェックリスト（確定）」節）
- 構成は**シンボル + ワードマークの横並び**。理由：シンボル単体を favicon（005）・OGP に流用でき、かつ Header で初見の訪問者にサイト名が読める。棄却した「ワードマークのみ」は favicon に切り出せる図形が残らない、「シンボルのみ」はサイト名が伝わらない
- 旧 ChatGPT 案 2 種は運営者が画像を渡す → 受領待ち

#### 旧案 2 種の受領と観察

運営者が `docs/design-drafts/phase1c-004/` に配置（`byte-lark.logo.png` / `byte-lark.logo2.webp`）。あわせて「このテイストにこだわらない、もっと洗練されたものがよい」と指示。

- 案1（png）：冠羽のある鳥が右向きに飛び、長い尾が左下へ。背景に開いた円、右下に遠近をつけた二進数
- 案2（webp）：閉じた太い円の中を鳥が右上へ飛び、後ろに二進数の粒が航跡として散る
- 引き継ぐ発想：冠羽（ヒバリの識別点）、上昇の姿勢、**飛跡がデータになる**という見立て。案2 の構図は Hero の「点線の軌跡」と発想が一致していた（`stroke-dasharray="1 10"` の刻みがそのままビットの粒）
- 捨てた要素：読める二進数（24px でも 16px でも完全に潰れる）、閉じた太い円（favicon で円が主役に見える）、ラスタの細密描写（合格条件 6 のパス構成と両立しない）

#### ラウンド1 の判定：全案ボツ（運営者）

「GPT の案と比べて明らかに見た目がしょぼい。劣化させないでほしい」。妥当な指摘なので受け入れ、原因を 3 点に整理した。

- 16px で読めるという条件を最初の一筆から効かせた。小さくても成立する形を先に決めると造形は必ず平凡に落ちる。主ロゴを先に作り、小サイズ用は別に簡略版を起こすのが正しい順序
- Hero の飾り（隅に 30% の透明度で置く装飾）をロゴ級の形として引き伸ばした。装飾は拡大してもロゴにならない
- 旧案から引き継ぐべきだったのは「鳥」ではなく**構図と線の質**だったのに、モチーフだけ抜き出して構図を捨てた

運営者判断：(1) 旧案をベクター化して磨く路線に切り替え、(2) 合格条件 3 を改訂（主ロゴは 24px 以上、16px は簡略版で担保）。

#### ラウンド2（提示物: `docs/design-drafts/phase1c-004/round2.html`）

旧案2（webp）の輪郭をそのままベクターに起こし、ブランド色を乗せた。線と構図は旧案のまま。

- ベクター化は自前実装（コンテナに potrace が無い）。marching squares で輪郭 → Ramer-Douglas-Peucker で節点削減 → Catmull-Rom を三次ベジェに変換。さらに包含関係から「外郭 + 穴」の図形単位にまとめ、部品ごとに色を変えられるようにした。スクリプトは scratchpad（`trace.mjs` / `shapes.mjs` / `gen-round2.mjs`）に置いてあり、成果物は SVG なので確定後は不要
- 変更点は 3 つだけ：① 単色 → 円＝朝日 sun / 鳥＝空 sky ② 胴の下に残っていた微小なノイズ（元画像由来）を削除 ③ 二進数の扱い
- 二進数の扱いで 2 案：**A** 読める大きさの数字だけ残す（旧案に最も近い）／**B** 数字をやめ、Hero の点線と同じ語彙＝ビットの粒に置き換える
- 小サイズ版：航跡を外した「円 + 鳥」と、「鳥のみ」。16px はこのどちらかで担保。Header に鳥のみを置いた実寸プレビューも併記
- 色違い（空色 1 色）・モノクロ・白抜きも同一画面に並べてある

#### ラウンド3（提示物: `docs/design-drafts/phase1c-004/round3.html`、2026-08-01）

画像生成の反復（ChatGPT/Gemini 各3世代、`ChatGPT*.png` / `Gemini*.png`）を経て方針が定まり、ベクター組み立てに移行：

#### ラウンド3の差し戻しと分析の訂正（運営者、2026-08-01）

- ラウンド3（均一幅の太リング）は「スタイリッシュでない」で差し戻し。原因は当方の観察ミス：旧案2のリングを「均一な太さ」と誤読していたが、実際は左下が太く右上へ細るテーパーの筆致で、動きはそれが作っていた。均一な太い弧の断片ではただの輪切りになる
- 数字の評価も分解して確定：旧案2の滝は「構造（扇状・遠近）は飛翔感の表現として最良、実行（数密度・乱回転・字の潰れ）は不良」。構造は採り、実行は規律化する
- レイアウト実験を Gemini にやらせる案は不採用（運営者提案に対し当方が反対、合意）：画像生成は毎回全体を描き直すため統制比較が成立しない。固定素材上のレイアウト実験はベクター作図で行う

#### ラウンド4の差し戻しとラウンド5（提示物: `docs/design-drafts/phase1c-004/round5.html`、2026-08-01）

- ラウンド4差し戻し。運営者評価：10案とも数字に飛翔感・絵力がなく、少量の数字がかえって貧相。数字が下部の場所を取ることで鳥が上に寄り、円の下側がスカスカ。「旧案2の数字のほうが圧倒的に見栄えがいい」
- 当方の分析（同意）：ラウンド4の失敗は SVG の制約ではなく設計判断の誤り。パラメトリックな軌道に大きめの粒を 4〜8 個置く方式では、旧案2 の滝が持つ「密度の勾配（腹元は細かく、外縁ほど大きく）による遠近と量感」が出ない。以前の「旧案2 は粒が多すぎて灰色ノイズ」という批判は 48px 以下の縮小時にのみ妥当で、表示サイズでは密度こそが絵力の源泉だった。小サイズ問題は鳥単体版（favicon 方針）で解決する話であり、滝を薄める理由にならない
- 事実発見：旧案2 の数字の滝は s2b.json のトレース時点で 52 図形（#3〜#54）としてベクター化済みだった。「そのまま使う」に技術障害なし（フォント化・アウトライン化も不要）
- ラウンド5 は 3 案：A = 滝を無加工で流用（52個）／B = 面積 95px² 未満の潰れ粒だけ間引き（33個）／C = 130px² 未満間引き + 1.14 倍（21個）。自己評価は A 推し（勾配が保たれ量感最良）、C は勾配が失われ却下相当
- ラウンド消化：1 ボツ + 2 差し戻し + 3 差し戻し + 4 差し戻し / 上限 5（Decision #15）。ラウンド5 が最終ラウンド

#### ラウンド5の差し戻しと上限延長（2026-08-01）
