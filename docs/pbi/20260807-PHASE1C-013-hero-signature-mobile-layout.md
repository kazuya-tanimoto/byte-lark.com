Status: InProgress

## 誰が

## 何をできる
- Hero 右下の署名要素「揚雲雀の軌跡」が、スマホ幅でボタンと重ならず、軌跡の点線が見える状態で表示される。鳥は昇っている途中に見え、Career 以降の位置は現状のまま保たれる

## なんのために
- 現状スマホでは 3 つの不具合がある（PHASE1C-011 検証で発見、運営者確認 2026-08-06）
  - 320px で鳥がお問い合わせボタンに 16×16px 重なる（390px でも軌跡の点線がボタンの裏に隠れる）
  - `opacity-30`（640px 未満）と点線自身の `opacity="0.55"` の二重掛けで実効 0.165 になり、軌跡が見えず「太陽と鳥だけ」に見える
  - 軌跡の終点が viewBox (250, 60) で鳥の胴の真下に刺さっており、尾の先端 (227, 67.8) から伸びていない
- 関連: docs/design-direction.md §5（署名要素「揚雲雀の軌跡」）、PHASE1C-008（署名要素の実装）、PHASE1C-011 実装ログ

## 技術メモ
- 想定セッション数: 1
- 関連ファイル: `src/components/Hero.astro`（装飾 SVG と Hero 本体）、必要なら `src/styles/global.css`
- モック: `docs/design-drafts/phase1c-013/index.html`（スマホ枠 / PC 枠を並べて方式を切り替える入口）、`page.html?mode=diveup`（採用案の単体表示）。鳥のパスは Hero.astro の実体を抜いて生成しているので、実装時も描き直さない
- 採用案の作り（モックの CSS 相当）
  - スマホ用は横長の別構図（viewBox 320×130）。鳥をボックス上端に置き、軌跡は尾から左下へ降ろす
  - 装飾をボタンの直後に通常フローの要素として置き、`margin-top: 16px` / `margin-bottom: -153px` で下へはみ出させる。Hero の `overflow` を外し、後続セクションが上に被さることで軌跡が隠れる
  - 重なり順は DOM 順で解決する（装飾に正の z-index を付けない。`.inner` の z-index を外す必要がある）
  - 640px 以上では従来の構図（viewBox 320×180、右下絶対配置）に戻す
- 検討したが不採用（PHASE1C-011 の議論、モックで比較済み）
  - 背景レイヤー化（`position: fixed` で本文の下）: スマホはカードが幅いっぱいを占めるため装飾がほぼ隠れる。Hero を透明にすれば見えるが、面の設計（design-direction §5 の wash → bg グラデーション）の変更が必要
  - 軌跡を 42 度まで立てる案: PC の 24.6 度から 18 度ずれ、PC とスマホで別物に見える
  - 現行構図を縮小するだけの案: 320px で鳥がボタンに 14×24px 重なり、解決しない
- 触ってはいけない領域: 確定デザイントークンの値（PHASE1C-002 / 003）、ロゴ・鳥のパス形状そのもの（PHASE1C-004 確定意匠）

## 実装ログ（着手後に追記、中断時は必須）

### 2026-08-07 実装 + ローカル検証（push 前まで）

やったこと：

1. `src/components/Hero.astro` を書き換え
   - 鳥のパスを frontmatter の `larkPath` に切り出し、PC 用・スマホ用の 2 構図から参照（形は PHASE1C-004 の確定意匠、描き直していない）
   - PC 用（`hidden sm:block`）：viewBox 320×180 の従来構図のまま。軌跡の終点だけ `250 60` → `222 71`（尾の先）に変更
   - スマホ用（`sm:hidden`）：viewBox 320×130 の横長構図を新設。ボタンの直後に通常フローの要素として置き、`mt-4` + 負の下マージンで Hero からはみ出させる
   - セクションは `overflow-visible sm:overflow-hidden`。スマホだけ装飾がはみ出せるようにする
2. `src/pages/index.astro` の `<main>` に `relative` を追加。位置指定の要素どうしは DOM 順で重なるため、後ろにある main が装飾の上に来る（＝はみ出した軌跡がカードの裏に回る）
3. 負のマージンを px から % へ変更
   - 当初 `-mb-[153px]`（モックの実測値）にしたが、この SVG は `w-full` なので高さが幅に比例する。px 固定だと 639px 幅で Hero が 110px 伸びることが計測で判明
   - margin の % は包含ブロックの幅基準なので、`-mb-[45%]` にすると高さと同じ比率で追従する

検証（変更前は CF branch alias、変更後はローカル preview。どちらも `fonts.ready` を待ってから iframe で実測）：

- 鳥の上端とお問い合わせボタンの下端の距離：20〜24px（幅による）
- 640px の境目で構図が入れ替わることを確認（639px = 320×130、640px = 320×180、二重表示なし）

- ローカル スクショ：390px / 320px / 1280px

学び：

- モックで「軌跡がカードの裏に隠れる」と説明していたが、実際は線がカードの 2px 上で終わっていただけだった。わざと重ねて確認したところ、対策なしでは線がカードの**上**に描かれる（Hero が position 指定あり、後続セクションが position 指定なしのため、描画順で Hero の子が上に来る）。main に `relative` を足して解決した。見えているものを根拠に「隠れている」と判断してはいけない
- モックの実測値をそのまま px で持ち込むと、可変幅では別の幅で破綻する。比率で効く指定（% マージン）に置き換えて全幅で確認する
