### 2026-06-13 着手・実装

やったこと:
- Vitest 単体テスト追加：`src/lib/{utils,og,jsonld}.test.ts`、`src/components/CategoryFilter.test.tsx`（jsdom + RTL、SSG 済み DOM を fixture で再現）。`yarn test:run` 16 件パス
- `vitest.config.ts` を `include: src/**/*.test.{ts,tsx}` に更新（E2E を Vitest 対象外に）。PnP で `vitest/config` の型拡張が効かないため cast で回避（既存パターン踏襲）
- E2E 追加：`tests/e2e/{navigation,blog,a11y}.spec.ts`（全ページ遷移 / Header ナビ / 404 / 一覧→詳細 / カテゴリフィルタ / axe）
- 依存追加（運営者の別ターミナル）：`@axe-core/playwright @testing-library/react @testing-library/dom jsdom`

学び・つまずき:
- 初回 E2E で 14 失敗。うち 13 は環境要因：Playwright が `reuseExistingServer` で `:4321` に居座る無関係な旧サーバ（`/` しか返さない dev サーバ）を再利用していた。現ビルドを別ポートで preview すると全ルート 200 で正常。対策として a11y.spec に `expectedStatus` 検証を追加し、誤ったサーバを掴むと axe が素通りせず失敗するようにした
- 旧サーバを止めて再実行（25 passed / 3 failed）。最初の run では 404 で隠れていた **`link-in-text-block`（serious、WCAG 1.4.1）** が /about・/contact・/privacy で顕在化。本文中のインラインリンクが既定で下線なし・色のみで区別されていたのが原因
- 修正：about / contact / privacy の本文インラインリンクを `hover:underline` → `underline`（常時下線）に変更。`color-contrast` と違い仮カラーに依存しない構造的な指摘なので 1c 送りにせず即修正。index / 404 の独立リンク（「すべて見る →」等）は本文中でなく axe も問題視しないため未変更

想定外・申し送り:
- **color-contrast を Phase 1c まで除外**（運営者判断 2026-06-13）。仮 HEX の primary / hibari-sky `oklch(0.685 ...)` が白背景で約 2.8:1（AA 4.5:1 未満）。色は計画上 1c で確定 HEX に置換のため、`a11y.spec.ts` で `color-contrast` ルールを `disableRules` で一時除外。**1c で確定 HEX 反映時に除外解除して再有効化すること**（site-plan §6.5.2 a11y 追跡 / NFR-02 の完全充足は確定 HEX 後）
- E2E 実行はサンドボックス外（運営者ターミナル）。Claude 側では Playwright test runner の Chromium 起動不可（macOS Mach port 権限）。一方 MCP Playwright のブラウザは起動可で、UI スクショ確認はそちらで実施した
- **手順遵守の反省**：UI 変更（リンク下線化）があるのに §7 のスクショ検証を飛ばして一度 Done にしかけた。原因は §7 ゲートが CLAUDE.md にしか無く PBI 受け入れ条件に無かったこと。再発防止として §7 検証 2 項目を全 PBI の受け入れ条件に常設化（README §4.6 ルール 7 / テンプレ / INDEX ガード / CLAUDE.md draft 手順）。本 PBI はその初適用
