# 訪問者はどのページでも右下のボタンでページの先頭に戻れる

Status: Done
Started: 2026-08-25
Completed: 2026-08-25

## 誰が

- 訪問者（記事ページに限らず全ページの利用者）

## 何をできる

- どのページでも、読み進めたあと右下のボタンでページの先頭に戻れる
- フッターまで読み終えた直後でもボタンは消えず、そのまま先頭に戻れる

## なんのために

- 現行ボタンは「見た目はページ先頭へ戻る上向き矢印、実際の動きは目次への移動」で、記号と挙動が
  食い違う（`src/layouts/PostLayout.astro:166-185` のアイコン / `:314-320` のクリック処理）
- 目次は記事ヘッダーの直下にあり、ページ先頭との差はヘッダーの高さぶんだけ。挙動を分ける価値が薄い
- 一番上に戻りたくなるのは最後まで読み終えた瞬間だが、現行はフッターが見えるとボタンを隠す
  （`:302-313`）。その瞬間にボタンが消える設計で、機能として逆向き
- 出所: 2026-08-24 運営者依頼。monotrip.jp で同じ見直しを決定済み（monotrip repo の
  `docs/site-plan-decisions.md` Decision #30 / backlog M1-010）。monotrip の実装は byte-lark
  PHASE1D-015 の踏襲で、今回 4 条件（記事ページ限定 / 目次戻り / フッターで消える /
  `xl:hidden`）が byte-lark の現行実装と一致することを確認した
- 関連: site-plan Phase 1e（公開後の運用・改善、Decision #31 の「公開直後の小さな手入れ」枠）/
  PHASE1D-015（現行ボタンの導入元）

## 技術メモ

- 想定セッション数: 1
- 実行環境: 実装・スクショ確認は母艦（`yarn dev` + MCP Playwright）でもコンテナ
  （repo の Playwright）でも可。E2E スイートは draft PR 経由の CI で検証（母艦ローカル実行不可）
- 現行実装:
  - ボタン本体: `src/layouts/PostLayout.astro:166-185`（`fixed right-4 bottom-5 z-40 size-11`、
    矢印 SVG、`xl:hidden`、`hidden`/`flex` をスクリプトが掛け替え）
  - 表示制御とクリック: 同 `:283-321`。「読み始めでは出さない」は目次 / 記事ヘッダー
    （`tocMobile ?? postHeader`）を IntersectionObserver で見る方式。フッター用 observer は
    `rootMargin: 0 0 -64px 0` でボタンと重なり始める位置から隠す
- 全ページ化すると anchor（目次 / 記事ヘッダー）が無いページが出る。出現判定はスクロール量基準
  （例: 1 画面ぶん = `window.innerHeight`）に置き換えると全ページで成立し、E2E の
  「ページの高さに依存しない出し方」もこれで書ける
- フッターの静的確認（2026-08-24）: モバイルは 1 列 grid でリンク左寄せ
  （`src/components/Footer.astro:9` / `:28-44`）、最下部の © 行のみ中央寄せ（`:71-74`）。
  右下のボタンとは重なりにくい見込みだが、実表示の確認は受け入れ条件で行う
- `src/components/ContactForm.tsx:297` に送信完了時の自前スクロール（ページ先頭へ）あり。
  本ボタンとは独立で干渉しない見込み（実装時に contact ページで確認）
- 追従目次の現在地ハイライト（PHASE1C-009、`PostLayout.astro:188-237`）と目次リンクの
  履歴置き換え（PHASE1D-015、同 `:254-281`）は今回の対象外。触らない
- monotrip 側の対応 PBI は M1-010（猫頭意匠の採否 + 挙動変更）。byte-lark に意匠の話は無いので
  挙動変更のみを横展開する

  記事ページを 1280×720 でスクロールした状態のスクショで、右カラムの追従目次とボタンが

  - 追従目次とボタンは xl のどの幅でも重ならない。横の空きは 1280px で 56px、1366px で 99px、
    1440px で 136px、1920px で 376px。最も詰まるのがちょうど 1280px で、そこから広げるほど空く
    （本文コンテナが `max-w-[1080px]` の中央寄せで、ボタンは常に画面右端から 16px のため）。
    縦は高さ 900px で目次下端 645 / ボタン上端 836

    （1280×720 実測で Career 4686px / About 2153px / Privacy 2132px）

    現れてちらつく。目次は `sticky top-24` だが、親の `<aside>` が記事の終わりで尽きるため。
    `offsetParent` なら CSS の出し分けだけを読むのでこれが起きない
  - 出現しきい値ちょうどで上下すると 1 回切り替わる。出る境目と消える境目をずらす案は

    「読み始めでは出さない、それだけ」という決めごとが濁るため。あとから足せる
  - 受け入れ条件は「フッターが見えている間は出さない」テストを削除としていたが、削除だけだと

  - 記事ページ以外の E2E はトップページを選んだ。1280×720 で `/blog` は 1750px しかなく
    1 画面ぶん（720px）を超える余裕が 310px しか無い。トップは 2593px で余裕 1153px あり、
    記事の増減の影響も受けにくい

- 運営者の本番確認で不具合 2 件が見つかった：
  1. 出現しきい値「1 画面ぶん」が大きすぎ、/contact（1512×982 で可動域 527px）や

- 修正（`fix/back-to-top-visibility`、PR #68）：
  - しきい値を固定 300px へ。下限根拠 = ページタイトルが sticky ヘッダー裏に隠れ切る位置

  - E2E をしきい値 300px に追随、低い窓（1280×280）で目次が抜けたら出るケースを追加。
    コンテナのローカル実行で 41 件 green、CI（UI Tests / Quality Checks）も success

- 学び・つまずき：
  - セッション 1 の「画面内判定は目次が抜けた瞬間にちらつくから却下」は誤り。境目で 1 回
