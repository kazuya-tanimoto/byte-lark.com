# 訪問者は記事の途中から先頭へ戻れて、目次を使っても一覧へ戻れなくならない

Status: Done
Started: 2026-08-09
Completed: 2026-08-10

## 誰が
- 訪問者（PC / スマホ）

## 何をできる
- スマホで記事の途中から先頭（目次の位置）へ 1 タップで戻れる
- 目次から何度飛んでも、ブラウザの戻るで一覧へ戻れる

## なんのために
- 2026-08-09 の公開後実機確認（運営者）で挙がった記事ページの回遊性の指摘を解消する（site-plan Phase 1d）
- 特に目次の履歴は実害が出ている。目次のリンクは素のページ内リンクなので 1 クリックごとに履歴が 1 件増え、PC で目次を何度か使ったあと一覧へ戻ろうとすると戻るを大量に押すことになる

## 受け入れ条件
- [x] スマホ幅で、スクロール後に「上へ戻る」ボタンが出て、押すと記事先頭（目次の位置）へ移動する。読み始めの位置では出ないこと。本文やフッターのリンクに重ならないこと
- [x] 目次のリンクを押しても履歴が増えない。移動後にブラウザの戻るを 1 回押すと、記事に来る前のページへ戻る
- [x] 目次リンクの移動後も URL のハッシュが更新され、その状態のリンクを共有すると同じ位置が開くこと
- [x] OS の「視差効果を減らす」設定が有効なときは、移動が即時ジャンプのままであること（`global.css` の `scroll-behavior: smooth` は `prefers-reduced-motion: no-preference` で守ってある。JS 側でも同じ配慮を入れる）
- [x] 上記 2 点の E2E をブログ記事のテストに追加する
- [x] `yarn build` / `yarn check` / `yarn check:ts` / `yarn test:run` がエラーなし
- [x] ローカル スクショ確認（desktop + mobile）（CLAUDE.md §7）
- [x] CF preview スクショ確認（branch alias URL）（CLAUDE.md §7）
- [x] E2E / CI green 確認（push 後 `bash scripts/ci-status.sh` で UI Tests / Quality Checks が success）（CLAUDE.md §7）

## 技術メモ
- 想定セッション数: 1
- 関連ファイル：`src/layouts/PostLayout.astro`（目次・上へ戻る）、`tests/e2e/blog.spec.ts`
- スマホの目次は画面固定ではなく、記事の先頭に置いた普通のブロック（`xl:hidden`）。PC 側だけ `sticky top-24` の追従目次（PHASE1C-009）
- 履歴を増やさない移動は、クリックを横取りして移動させたうえで `history.replaceState` でハッシュを差し替える形。引き換えに戻るで記事内の移動を巻き戻せなくなる（これは今回の狙いどおり）
- 追従目次の現在地ハイライト（PHASE1C-009 の rAF + passive scroll）を壊さないこと

## 備考
- Gate である PHASE1D-009 より先に着手する
- 前後記事リンクは本 PBI から外し、Phase 1e（FR-19、記事 10 件到達時のカテゴリ別一覧）と同時に作る。2026-08-09 の運営者判断：前後リンクは「訪問者が見ている一覧の並び」と一致していないと使いづらいだけになる。今の絞り込みは `CategoryFilter.tsx` の `useState` のみで URL にも保存領域にも残らないため、追従させるには一覧の絞り込みを URL に持たせ、カードのリンクに印を付け、記事側で 3 通りの前後を出し分ける仕掛けが要る。1e で `/blog/tech` `/blog/life` が実 URL になれば同じことが仕掛けなしで成立するうえ、公開記事 3 本（tech 2 / life 1）では出るリンクがほとんどない

## 実装ログ（着手後に追記、中断時は必須）

### 2026-08-09

やったこと
- 着手時に運営者判断で前後記事リンクを Phase 1e へ移管し、本 PBI を「先頭へ戻る」「目次の履歴」の 2 件に縮小（判断の中身は備考）
- `PostLayout.astro` に記事内の移動用スクリプトを追加
  - 目次（本文先頭 / 追従の両方に `data-toc`）のクリックを横取りし、自分で `scrollIntoView` して `history.replaceState` でハッシュだけ差し替える
  - 移動先の見出しに `tabindex="-1"` を付けて `focus({ preventScroll: true })`。キーボード・読み上げの現在地も一緒に運ぶ（素の `focus()` は直後のスクロールと引っぱり合う。PHASE1D-013 の学び）
  - 修飾キー付き・中クリックは横取りしない（別タブで開く操作を殺さないため）
- xl 未満だけに出る「先頭へ戻る」ボタン（44px 円、右下）を追加。戻り先は目次があれば目次の位置（`scroll-mt-20` で sticky ヘッダー分を空ける）、無ければページ先頭
  - 表示判定は IntersectionObserver 2 本。戻り先が画面より上へ抜けたら出す / フッターが重なる位置まで上がってきたら引っ込める（後者は `rootMargin: "0px 0px -64px 0px"` で、ボタンが占める高さぶん判定を切り上げ）
- E2E を 3 本追加（`tests/e2e/blog.spec.ts`）：目次クリックで履歴が増えず戻るで一覧へ帰る / スマホ幅でボタンが出て目次の位置へ戻る / フッター表示中は出さない

実測（ローカル dev、iPhone 14 幅 + 1440px 幅）
- 目次を 4 回クリック → `history.length` の増分 0、URL ハッシュは毎回更新、戻る 1 回で `/blog` へ
- 共有相当（`/blog/<slug>/#見出し` を直接開く）→ 見出しが画面上端から 80px の位置に着地
- 視差効果を減らす設定：60ms 後に既に着地（1468 / 1468）。通常設定は 60ms 後 24 → 1s 後 1468 で滑らか。ボタン側も同じ（reduce で 478 / 478）
- ボタン：読み始めで非表示 → 2000px スクロールで表示（44×44、右 4 / 下 20px）→ 押すと目次が上端 80px へ、押した後は非表示 → 最下部（フッター表示中）で非表示。1440px 幅ではスクロールしても出ない
- 追従目次の現在地ハイライト（PHASE1C-009）はスクロール時・目次クリック後とも従来どおり点灯

学び・つまずき
- 目次が無い記事の分岐は普通に見ているだけでは通らないので、`addInitScript` で目次要素を消してから読み込ませて確認した（ページ先頭へ戻り、JS エラーなし）
- フッターとの重なり判定は「フッターが画面に入った瞬間」だと早すぎる。ボタンの実寸ぶん `rootMargin` で切り上げないと、まだ重なっていないのに引っ込む
