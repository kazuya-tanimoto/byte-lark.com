# 訪問者は記事を読み終えたあと、次の記事へ進んだり先頭へ戻ったりを迷わずできる

Status: NotStarted

## 誰が
- 訪問者（PC / スマホ）

## 何をできる
- 記事の末尾から前後の記事へ移動できる
- スマホで記事の途中から先頭（目次の位置）へ 1 タップで戻れる
- 目次から何度飛んでも、ブラウザの戻るで一覧へ戻れる

## なんのために
- 2026-08-09 の公開後実機確認（運営者）で挙がった記事ページの回遊性の指摘 3 件をまとめて解消する（site-plan Phase 1d）
- 特に目次の履歴は実害が出ている。目次のリンクは素のページ内リンクなので 1 クリックごとに履歴が 1 件増え、PC で目次を何度か使ったあと一覧へ戻ろうとすると戻るを大量に押すことになる

## 受け入れ条件
- [ ] 記事の末尾に前後の記事へのリンクが出る。「全記事の公開日順」か「同じカテゴリの中の公開日順」かは着手時に運営者へ提案して決める（どちらもビルド時に確定できる）
- [ ] 最初の記事に「前」、最後の記事に「次」が出ない（片側だけの表示が崩れないこと）
- [ ] 記事が 1 本しかないカテゴリでも壊れないこと
- [ ] スマホ幅で、スクロール後に「上へ戻る」ボタンが出て、押すと記事先頭（目次の位置）へ移動する。読み始めの位置では出ないこと。本文やフッターのリンクに重ならないこと
- [ ] 目次のリンクを押しても履歴が増えない。移動後にブラウザの戻るを 1 回押すと、記事に来る前のページへ戻る
- [ ] 目次リンクの移動後も URL のハッシュが更新され、その状態のリンクを共有すると同じ位置が開くこと
- [ ] OS の「視差効果を減らす」設定が有効なときは、移動が即時ジャンプのままであること（`global.css` の `scroll-behavior: smooth` は `prefers-reduced-motion: no-preference` で守ってある。JS 側でも同じ配慮を入れる）
- [ ] 上記 3 点の E2E をブログ記事のテストに追加する
- [ ] `yarn build` / `yarn check` / `yarn check:ts` / `yarn test:run` がエラーなし
- [ ] ローカル スクショ確認（desktop + mobile）（CLAUDE.md §7）
- [ ] CF preview スクショ確認（branch alias URL）（CLAUDE.md §7）
- [ ] E2E / CI green 確認（push 後 `bash scripts/ci-status.sh` で UI Tests / Quality Checks が success）（CLAUDE.md §7）

## 技術メモ
- 想定セッション数: 1
- 関連ファイル：`src/layouts/PostLayout.astro`（目次・上へ戻る）、`src/pages/blog/[slug].astro`（前後記事を `getStaticPaths` で props として渡す）、`tests/e2e/blog.spec.ts`
- 静的サイトのままで実現できる。カテゴリの絞り込みは `/blog/` の React 島が `data-blog-item` の表示・非表示を切り替えているだけで、選んだ状態は URL にも保存領域にも残らない（`CategoryFilter.tsx` は `useState` のみ）。記事ページ側に波及しないので、前後リンクはビルド時に確定できる
- スマホの目次は画面固定ではなく、記事の先頭に置いた普通のブロック（`xl:hidden`）。PC 側だけ `sticky top-24` の追従目次（PHASE1C-009）
- 履歴を増やさない移動は、クリックを横取りして移動させたうえで `history.replaceState` でハッシュを差し替える形。引き換えに戻るで記事内の移動を巻き戻せなくなる（これは今回の狙いどおり）
- 追従目次の現在地ハイライト（PHASE1C-009 の rAF + passive scroll）を壊さないこと
