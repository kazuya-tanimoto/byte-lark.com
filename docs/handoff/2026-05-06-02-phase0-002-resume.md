## §4 worktree 取り扱いルール（重要）

このセッションの混乱の主因は **`EnterWorktree` ツールが sandbox の writeable 範囲を worktree subtree に narrow する**こと。`/Users/kazuya/src/react-blog/.git/worktrees/phase-0-pbi-002/` への write が拒否されて git ops が `Operation not permitted` で詰まる。

### DO

- worktree に入る時は **プレーン `cd .claude/worktrees/phase-0-pbi-002`** を bash で実行
- 主作業はその CWD で進める
- worktree CWD 内から `git add` / `git commit` する：問題なく通る（session restart 後の挙動で実証済）

### DON'T

- **`EnterWorktree` ツールは使わない**（前回セッションで実証：sandbox narrow → git ops 不能 → ExitWorktree 必須の handoff コスト）
- worktree を新規 `git worktree add` で作り直さない（既存のものを使う）

### 万一 sandbox が narrow した場合の脱出

main repo CWD `/Users/kazuya/src/react-blog/` から `git -C .claude/worktrees/phase-0-pbi-002/ ...` で操作可能。

## §5 Claude sandbox 用 env vars（ローカル運用環境では不要）

Yarn 4 / yarn dlx を Claude sandbox 内で動かすために以下を export：

```bash
export COREPACK_HOME="$TMPDIR/corepack"
export YARN_HTTP_PROXY="http://localhost:56072"
export YARN_HTTPS_PROXY="http://localhost:56072"
export YARN_GLOBAL_FOLDER="$TMPDIR/yarn-berry"
```

これら 4 つは Claude sandbox の network proxy 経路と writeable 制約を yarn 4 に教えるため。proxy port は session 起動時の `HTTP_PROXY` env から取得（`env | grep -i proxy` で確認）。

通常端末（運営者の terminal）でこれらは不要。
